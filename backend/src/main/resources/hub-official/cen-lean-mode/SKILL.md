# 최소 구현 모드

가장 좋은 코드는 쓰지 않은 코드다. 이 모드가 켜져 있는 동안, 코드를 쓰거나 고치기 전에 항상 `references/checklist.md` 의 점검 순서를 따른다.

## 켜고 끄기
- 켜기: `/cen-lean-mode` (강도: `/cen-lean-mode 가볍게`, `/cen-lean-mode 강하게` — `references/levels.md`)
- 끄기: 사용자가 "최소 구현 모드 꺼", "보통 모드", "stop lean" 이라고 하면 바로 평소대로 돌아간다.
- 한 번 켜면 끌 때까지 이 대화의 모든 코딩 작업에 적용한다.

## 핵심 규칙
1. 쓰기 전에 점검 순서(필요성 → 기존 코드 → 표준 라이브러리 → 플랫폼 기능 → 설치된 의존성 → 최소 코드)를 따른다.
2. 변경 범위는 요청을 해결하는 데 필요한 파일과 줄로만 한정한다.
3. 작업 끝에 `templates/summary.md` 형식으로 뺀 것과 재사용한 것을 짧게 알린다.

## 파일 구성
- `references/checklist.md` — 쓰기 전 점검 순서와 쓰는 방식
- `references/levels.md` — 강도(가볍게·보통·강하게)
- `templates/summary.md` — 작업 끝에 알릴 내용
- `examples/before-after.md` — 줄이기 전·후 예시

## 하지 않는 것
- 보안·데이터 손실 방지·접근성처럼 빠지면 문제가 되는 것은 줄이지 않는다.
- 사용자가 명시적으로 요청한 기능을 임의로 빼지 않는다. 과하다고 보이면 빼기 전에 묻는다.
- 짧게 만들려고 읽기 어려운 코드(한 줄에 몰아넣기, 의미 없는 이름)를 쓰지 않는다.

## 웹에서 한 번 실행할 때
CEN HUB 웹에서 요구사항·설계·코드를 넣으면, 점검 순서로 "만들지 않아도 되는 것 / 이미 있는 것으로 되는 것 / 줄일 수 있는 코드"를 표로 정리한다. 결과는 검토용 제안이다.

참고: 공개 프로젝트 Ponytail(DietrichGebert/ponytail)의 원칙을 참고해 사내용 한국어 지침으로 새로 썼다.
