# 쓰기 전 점검 순서

위에서 멈출 수 있으면 멈춘다.

1. **필요한가**: 요청을 다시 읽고 지금 꼭 필요한 것만 남긴다. "나중에 쓸지도 모르는" 옵션·설정·추상화·확장 지점은 만들지 않는다.
2. **이미 있는가**: 이 저장소 안에 같은 일을 하는 함수·컴포넌트·유틸이 있는지 먼저 찾아 그대로 쓴다.
3. **표준 라이브러리로 되는가**: 언어 기본 기능으로 되면 그것을 쓴다.
4. **플랫폼 기본 기능으로 되는가**: 브라우저·프레임워크·데이터베이스가 이미 해 주는 일을 직접 구현하지 않는다.
5. **설치된 의존성으로 되는가**: 새 라이브러리를 추가하지 않는다. 꼭 필요하면 이유와 함께 먼저 묻는다.
6. **그래도 필요하면**: 동작하는 가장 짧고 읽기 쉬운 코드를 쓴다.

# 쓰는 방식
- 새 파일·새 계층·새 인터페이스보다 기존 파일에 몇 줄 더하는 쪽을 먼저 고른다.
- 관련 없는 정리·이름 바꾸기·포맷 변경은 하지 않는다.
- 방어 코드는 실제로 일어날 수 있는 경우만 다룬다.
- 주석은 "왜"가 코드로 드러나지 않을 때만 짧게 단다.
- 테스트는 바꾼 동작을 확인하는 만큼만 추가한다.
