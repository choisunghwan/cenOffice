# 오류 로그 분석

## 사용 방법
서버 로그나 스택 트레이스(Caused by 포함)를 그대로 붙여 넣으면 최상위 예외와 가장 안쪽 원인, 애플리케이션 코드 위치 후보, 원인별 확인 순서를 표로 정리합니다.
규칙 기반 도구이며 외부로 전송하지 않습니다. 원인을 확정하지 않고 확인 순서를 제안합니다.
비밀번호·토큰·개인정보가 있으면 지운 뒤 사용하세요.

## 실행 예시
입력: java.lang.NullPointerException 이 포함된 스택 트레이스
결과: 예외 요약, 예외 연쇄, 코드 위치 후보, 확인 순서

## 수행 지침 (AI 에이전트용)
사용자가 오류 로그나 스택 트레이스를 주면 다음 순서로 정리한다. 로그에 없는 사실은 추측하지 말고 "확인 필요"로 표시한다.
1. 최상위 예외, 메시지, 가장 안쪽 `Caused by`(근본 원인 후보)를 표로 요약한다.
2. 예외 연쇄를 바깥에서 안쪽 순서로 나열하고, ERROR/WARN 줄 수와 시각 범위를 적는다.
3. 프레임워크·JDK 프레임을 제외하고 애플리케이션 코드(우리 패키지)의 클래스·메서드·줄 번호를 후보로 제시한다.
4. 예외 종류별(NPE, 제약조건 위반, 연결 실패, 타임아웃, 지연 로딩 등) 확인 순서를 근본 원인부터 최대 5개 제시한다.
5. 원인을 단정하지 않고 재현 조건과 수정 후 확인 방법을 마지막에 제안한다. 비밀번호·토큰·개인정보는 출력하지 않는다.
