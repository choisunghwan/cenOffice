# SQL 점검

## 사용 방법
세미콜론(;)으로 구분한 SQL 을 붙여 넣으면 문장별로 위험도(높음/중간/낮음)와 개선 제안을 표로 보여 줍니다.
정적 규칙만 사용하므로 데이터 양·인덱스·실행 계획은 반영되지 않습니다. 운영 DB 적용 전 실행 계획 확인과 검토가 필요합니다.
SQL 은 실행되지 않으며 외부로 전송되지 않습니다.

## 실행 예시
입력: DELETE FROM orders;
결과: WHERE 없는 DELETE — 높음

## 수행 지침 (AI 에이전트용)
사용자가 SQL을 주면 실행하지 말고 문장별로 점검한다. 데이터 양·인덱스·실행 계획을 모르면 모른다고 밝힌다.
- 높음: WHERE 없는 UPDATE/DELETE, DROP/TRUNCATE/ALTER, 조인 조건 없는 콤마 조인, 문자열 결합으로 만든 SQL(주입 위험).
- 중간: `SELECT *`, 앞부분 와일드카드 `LIKE '%값'`, WHERE 절의 컬럼 함수 가공, `NOT IN (서브쿼리)`, 100개 초과 IN 목록.
- 낮음: 조건·건수 제한이 없는 SELECT.
각 항목마다 "등급 / 문제 / 이유 / 개선안"을 표로 쓰고, 마지막에 문장 수와 등급별 건수를 요약한다. 운영 DB 적용 전 EXPLAIN 확인을 권고한다.
