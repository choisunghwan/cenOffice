# 테스트 설계 기법

| 기법 | 방법 | 예 (비밀번호 8~20자) |
|---|---|---|
| 정상 | 가장 흔한 올바른 사용 | 12자 비밀번호로 가입 |
| 동등 분할 | 같은 결과를 내는 입력끼리 묶어 대표값 하나씩 | 정상(8~20자) / 너무 짧음 / 너무 김 |
| 경계값 | 범위의 끝과 바로 바깥 | 7자(실패), 8자(성공), 20자(성공), 21자(실패) |
| 필수·형식 | 빈 값, 공백만, 잘못된 형식 | 빈 비밀번호, 공백 8칸, 한글 포함 |
| 상태 변화 | 순서·상태에 따라 결과가 달라지는 경우 | 5회 실패 후 잠금, 잠금 해제 후 로그인 |
| 권한 | 역할마다 되는 것과 안 되는 것 | 일반 사용자가 관리자 메뉴 접근 |
| 예외·오류 | 외부 오류·중복·동시 요청 | 같은 아이디 동시 가입, 서버 오류 시 안내 |
| 보안 입력 | 위험한 입력을 넣었을 때 | 스크립트 태그, 따옴표가 든 입력, 아주 긴 입력 |

- 요구사항 하나에 모든 기법을 쓸 필요는 없다. 그 기능에 의미 있는 것만 고른다.
- 숫자·길이·날짜 범위가 있으면 경계값은 꼭 넣는다.
