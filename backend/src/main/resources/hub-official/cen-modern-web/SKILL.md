# 모던 웹 코드 가이드

## 언제 쓰나요
- 오래된 화면 코드를 손볼 때, 지금은 브라우저가 기본으로 해 주는 일을 코드로 직접 하고 있지 않은지 보고 싶을 때
- 새 화면을 만들 때 요즘 권장 방식을 먼저 확인하고 싶을 때

## 입력
- HTML·CSS·자바스크립트(또는 리액트 등) 코드, 또는 "모달을 어떻게 만들지?" 같은 질문
- 선택: 지원해야 하는 브라우저(예: 사내 크롬·엣지 최신)

## 진행 방법
1. 코드에서 아래처럼 지금은 브라우저 기본 기능으로 대신할 수 있는 패턴을 찾는다.
   - 모달·팝업: div 와 직접 만든 포커스 가두기·ESC 처리 → `<dialog>` 와 showModal(), 단순 펼침 메뉴·툴팁 → popover 속성
   - 펼치기·접기: 직접 만든 토글 → `<details>`/`<summary>`
   - 레이아웃: float·절대 위치 계산·JS 로 높이 맞추기 → Flexbox·Grid, 부모 크기에 따른 변화 → 컨테이너 쿼리, 비율 유지 → aspect-ratio
   - 선택자·스타일: 부모를 꾸미려고 JS 로 클래스 붙이기 → `:has()`, 깊은 중첩 반복 → CSS 중첩, 색 계산 → color-mix()
   - 스크롤·애니메이션: 스크롤 위치 계산으로 나타나기 → IntersectionObserver, 화면 전환 효과 → View Transitions(지원 범위 확인)
   - 자바스크립트: XMLHttpRequest·jQuery.ajax → fetch 와 AbortController, 깊은 복사용 JSON 왕복 → structuredClone(), 날짜·숫자 표시 → Intl, 지연 로딩 → 이미지 loading="lazy"
   - 폼: 직접 짠 검증 → required·pattern·type 등 기본 검증과 :user-invalid
   - 접근성: 클릭 가능한 div → button, 이미지 alt 누락, 라벨 없는 입력칸
2. 바꿀 때마다 브라우저 지원 범위를 함께 적는다. 주요 브라우저(크롬·엣지·파이어폭스·사파리)에서 모두 되는 기능을 우선 권하고, 일부만 되면 "지원 범위 확인 필요"와 대안을 적는다.
3. 바꾼 코드 예시를 짧게 보여 준다(전체를 다시 쓰지 않고 바뀌는 부분만).

## 결과 형식
1. 요약: 바꿀 만한 곳 N군데, 효과가 큰 것 하나
2. 표: | 지금 코드 | 바꿀 방식 | 좋아지는 점 | 브라우저 지원 |
3. 바뀐 코드 예시
4. 그대로 두는 것이 나은 부분(있으면)

## 예시
입력: 버튼을 누르면 div 모달을 display 로 켜고, ESC 키와 바깥 클릭을 직접 처리하는 코드
결과: `<dialog>` + showModal() 로 바꾸면 ESC 닫기·포커스 가두기·배경 막기를 브라우저가 처리 → 코드 30줄 감소

## 주의할 점
- 동작이 같은지 꼭 확인하도록 안내한다. 결과는 검토용 제안이며 실행해 보지 않았다.
- 브라우저 지원은 바뀔 수 있으므로 중요한 화면은 사내 표준 브라우저에서 확인한다.
- 잘 동작하는 코드를 유행 때문에 바꾸라고 하지 않는다. 코드가 줄거나, 접근성·성능이 나아지는 경우만 권한다.
- 참고: Chrome·Edge·Firefox·MDN 팀의 공개 프로젝트 Modern Web Guidance 의 취지를 참고해 사내용으로 새로 썼다. 전체 안내서가 필요하면 Claude Code 에 공식 플러그인을 직접 설치해 쓸 수 있다.
