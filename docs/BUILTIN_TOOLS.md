# 내장 업무 도구와 재사용 중심 홈

## 실제 구현

- `cen-fp-estimator`: XLSX·UTF-8 TXT/MD를 읽어 EI/EO/EQ 후보와 검토 근거를 생성하는 로컬 규칙 엔진. ILF/EIF·복잡도·FP 합계 확정은 제공하지 않습니다.
- `cen-proposal-writer`: DOCX·XLSX·UTF-8 TXT/MD 원문을 요구사항 대응표와 제안서 구성 초안으로 변환합니다. 고객 실적·예산·일정은 만들어내지 않습니다. 자유문 메모는 보존하며 지시를 실행하지 않습니다.
- 실제 파일 내용을 처리하며 API 키, Mock 응답, 외부 네트워크 전송 없이 동작합니다. 생성형 LLM을 호출하는 도구가 아닙니다. 기존 LLM Runtime과 별도로 `builtin-local` 어댑터를 사용합니다.
- 승인된 내장 SKILL.md를 기존 Registry에 최초 한 번 설치합니다. 직원이 같은 이름을 먼저 등록했으면 덮어쓰지 않으며, 시스템 소유자가 아닌 리소스에는 내장 실행 권한을 주지 않습니다.
- 기존 인증·접근제어·실행 이력·감사 로그·중복 및 빈도 제한을 재사용합니다. 스키마 변경은 없어 신규 마이그레이션이 필요하지 않습니다.

## 사용 방법

1. WORKSPACE → 도구 둘러보기 → **우리 회사의 AI 도구**에서 FP 산정 도우미 또는 제안서 작성 도우미를 선택합니다. 별도 데모 영역은 없습니다.
2. 소개와 등록된 예시를 확인하거나 **사용하기**로 파일 입력 화면을 엽니다.
3. 자료 선택 → 초안 생성 → 검토 → 다운로드. FP는 Excel에서 열 수 있는 UTF-8 CSV, 제안서는 Markdown입니다. 네이티브 XLSX/DOCX 결과 생성은 아직 제공하지 않습니다.
4. 카드의 별표로 즐겨찾기합니다. 사용자별 이 브라우저에 저장되며 서버/다른 기기와 동기화되지는 않습니다. 최근 즐겨찾기 12개를 홈에 표시합니다.
5. 최근 사용은 본인의 실제 실행 이력에서 표시합니다. HOT은 기존 KPI 제외 규칙에 따라 집계한 누적 실행 수가 있고 현재 실행 가능한 도구만 표시합니다. 데이터가 없으면 순위를 만들지 않습니다.

## 파일 처리 경계

- 최대 3개, 프론트엔드 합계 5MB, 서버 multipart 요청 6MB, 파일당 5MB.
- 추출한 자료 합계 12,000자·80행. 초과하면 거부하며 일부만 읽고 완료라고 표시하지 않습니다.
- OOXML은 메모리에서 읽고 원본 파일을 저장하지 않습니다. 실행 입력(추출 텍스트)·결과는 기존 DB에 보관하며 요청자와 관리자가 조회할 수 있습니다.
- ZIP 경로·중복 항목·압축 해제 용량 제한 및 XML 외부 엔티티 차단. 수식·매크로·외부 링크는 실행하지 않습니다. XLSX 수식 값은 저장된 캐시가 있으면 읽으며 재계산하지 않습니다.
- PDF/OCR/소스 ZIP, 회사별 FP 양식에 대한 의미 기반 열 매핑, 공식 FP 합계, 생성형 제안서 작성은 미구현입니다.

## API

- `GET /api/hub/builtins`: 가시 범위 내 내장 도구 상세.
- `POST /api/hub/builtins/{id}/documents`: 인증된 사용자만 multipart `files`와 선택 `instructions`를 제출. 승인·등록 소유자 검증 후 기존 실행 서비스에 접수.
- 기존 `/api/hub/executions/{id}` 및 실행 이력 API로 상태·결과 조회.

## 검증

`BuiltinToolsTest`: XLSX shared/inline strings·DOCX 읽기, 실제 입력에 따른 분류·초안 생성, UTF-8·지원 형식·경로 탐색·XXE·압축 폭탄·길이 제한.

`HubApiTest`: 인증된 업로드 및 결과·개인 실행 접근제어·동일 요청 중복 방지·미인증 접근·비내장 대상 및 지원하지 않는 파일 거부.

전체 회귀 검사: 70건 중 69건 통과, 기존 `PmApiTest` 한 건은 5초 상태 대기 제한으로 실패. 해당 클래스 단독 재실행에서는 5건 모두 통과했습니다. 전체 일괄 실행이 한 번에 통과했다고 보고하지 않습니다. 신규 내장 테스트 7건(단위 5건·통합 2건)은 통과했습니다.

프론트엔드 TypeScript 및 Vite 빌드 통과. Chrome에서 업무 사진, 통합 목록, 별표 토글, 사용하기 → 실제 파일 입력 화면 진입을 확인했습니다. 로컬 DB의 KPI를 테스트 횟수로 늘리지 않기 위해 브라우저에서 실행 제출은 하지 않았으며 실제 문서 처리·성공 결과·실행 접근제어는 격리된 H2 통합 테스트로 검증했습니다.
