# 점검 항목

위에서부터 순서대로 본다. 해당 언어·프레임워크에 맞지 않는 항목은 건너뛴다.

## 1. 정확성
- null·빈 값: 메서드 반환값, Map 조회, 외부 입력을 확인 없이 바로 쓰는가(NPE·undefined 접근)
- 경계값: 반복문의 시작·끝(off-by-one), 빈 목록·한 건·최대 건수에서 동작하는가
- 예외 처리: 예외를 잡고 아무것도 하지 않는가(삼킴), 너무 넓게 잡아 원인을 가리는가
- 조건식: 부정·우선순위가 의도와 반대인가, 같은 비교를 == 와 equals 로 섞어 쓰는가
- 자원: 파일·커넥션·스트림을 닫지 않는가(try-with-resources, finally)
- 시간·숫자: 시간대(UTC/KST) 혼동, 정수 나눗셈·오버플로, 부동소수점 금액 계산

## 2. 보안
- SQL 인젝션: 입력값을 문자열로 이어 붙여 쿼리를 만드는가 → 자리표시자(?)·바인딩 사용
- XSS: 사용자 입력을 검증·이스케이프 없이 HTML 로 출력하는가(innerHTML, dangerouslySetInnerHTML)
- 경로 조작: 입력값으로 파일 경로를 만들 때 `..` 등을 막는가
- 인증·권한: 새 API·화면에 로그인·권한 확인이 빠졌는가, 남의 데이터를 id 만 바꿔 볼 수 있는가
- 비밀 정보: 비밀번호·키·토큰이 코드나 로그에 들어가는가
- 역직렬화·동적 코드 실행: 외부 입력으로 객체를 만들거나 코드를 실행하는가

## 3. 동시성
- 여러 요청이 같이 바꾸는 상태(정적 필드, 싱글턴 빈의 필드)를 잠금 없이 고치는가
- 스레드에 안전하지 않은 객체(SimpleDateFormat, HashMap 등)를 공유하는가
- "확인 후 처리"가 원자적이지 않아 경쟁 상태가 생기는가(재고 차감, 중복 가입)
- 비동기 작업의 실패가 무시되는가

## 4. 성능
- 반복문 안에서 DB·네트워크를 부르는가(N+1)
- 필요 없는 전체 조회, 페이지 없는 목록 조회
- 큰 데이터 전체 복사, 반복되는 정규식·객체 생성
- 인덱스가 필요한 조건으로 자주 조회하는가

## 5. 유지보수 (중요한 것만)
- 의도를 알기 어려운 이름, 같은 로직의 중복
- 테스트가 없는 중요한 분기
- 쓰지 않는 코드·설정이 새로 생겼는가
