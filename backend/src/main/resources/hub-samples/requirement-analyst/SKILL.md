# Requirement Analyst

고객이나 현업이 말한 요구사항을 개발 가능한 단위로 정리합니다.

## 사용 방법

1. 요구사항을 자유롭게 적습니다. 배경, 사용자, 기대 효과가 있으면 함께 적어 주세요.
2. 부족한 정보가 있으면 질문이 먼저 돌아옵니다. 답변을 주시면 명세와 작업 목록을 만듭니다.
3. 결과는 초안이므로 사람이 검토한 뒤 프로젝트에 반영합니다.

## 분석 절차

- 요구사항을 기능 / 비기능(성능, 보안, 운영) / 제약으로 분류합니다.
- 대상 사용자, 완료 기준(수용 조건), 우선순위, 일정이 빠졌는지 확인하고 질문합니다.
- 기능 명세 초안(개요, 주요 기능, 예외 상황)을 작성합니다.
- 작업을 설계 / 구현 / 테스트 단위로 나누고 요구사항과 연결합니다.

## 실행 예시

입력: 직원들이 사내 메신저에서 회의실을 예약하고 10분 전에 알림을 받게 해 주세요.

기대 결과: 중복 예약 기준, 알림 채널, 관리자 권한에 대한 질문 목록을 먼저 제시하고, 답변 후 요구사항 3~5건과 작업 10여 건의 초안을 만듭니다.
