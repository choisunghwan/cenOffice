# 점검 기준

## 1. 쓸모
- 실제 업무 하나를 분명히 해결하는가. "무엇이든 도와줌"처럼 범위가 없는 스킬은 보완 필요.
- 입력을 받아 결과를 만드는 일이 실제로 있는가. 입력을 그대로 옮기거나 고정 문구만 내보내는 스킬은 반려 권고.

## 2. 명확성
- description 만 읽고 "무엇을 하고 언제 쓰는지" 알 수 있는가(20자 이상, 한두 문장).
- title 이 업무 이름으로 쓰였는가(예: "주간 보고서 작성").
- 진행 방법이 단계로 쓰여 있어 다른 사람이 같은 결과를 기대할 수 있는가.

## 3. 완결성
- 다음 내용이 있는가: 언제 쓰나요(또는 사용 방법) · 입력 · 진행 방법 · 결과 형식 · 예시 · 주의할 점
- SKILL.md 가 가리키는 파일(references/…, templates/… 등)이 실제로 함께 올라왔는가.
- 예시가 입력과 결과를 모두 보여 주는가.

## 4. 안전
- 비밀번호·API 키·개인정보·내부 서버 주소가 들어 있지 않은가.
- 외부 사이트 접속, 명령어·스크립트 실행, 파일 삭제를 지시하지 않는가.
- AI 에게 사실을 지어내게 하거나, 검토 없이 확정하게 하지 않는가. 결과가 검토용 초안임을 밝히는가.
- AI 에게 원래 지침을 버리거나 역할을 바꾸라고 하는 문장(프롬프트 인젝션)이 없는가.

## 5. 중복·범위
- 이미 공개된 스킬과 이름·하는 일이 거의 같지 않은가(같으면 기존 스킬 개선을 권한다).
- 공개 범위(전사·팀)에 맞는 내용인가. 특정 개인만 쓰는 내용이면 팀 공개를 권한다.

## 판정
| 판정 | 기준 |
|---|---|
| 통과 | 높음·중간 문제가 없다 |
| 보완 필요 | 중간 문제가 있거나, 높음 문제가 있지만 고치면 해결된다 |
| 반려 권고 | 안전의 높음 문제(비밀 정보, 위험한 실행 지시, 인젝션) 또는 쓸모가 없다 |
