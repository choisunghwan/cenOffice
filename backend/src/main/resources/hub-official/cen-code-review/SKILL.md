# 코드 리뷰

## 언제 쓰나요
- 머지 요청(PR) 전에 변경 내용을 한 번 더 확인하고 싶을 때
- 다른 사람이 짠 코드를 검토하는데 놓친 부분이 없는지 보고 싶을 때

## 입력
- `git diff` 결과, 또는 파일 내용(파일 이름과 함께 붙이면 좋습니다)
- 선택: 언어·프레임워크, 이 변경의 목적 한 줄

## 진행 방법
1. 입력이 diff 이면 추가·변경된 줄(+)을 중심으로 보고, 주변 맥락은 필요한 만큼만 참고한다.
2. `references/checklist.md` 의 항목(정확성 → 보안 → 동시성 → 성능 → 유지보수) 순서로, 실제로 문제가 될 수 있는 것만 찾는다.
3. 각 문제의 심각도는 `references/severity.md` 기준으로 매긴다.
4. 결과는 `templates/report.md` 형식으로 쓴다. 예시는 `examples/` 폴더를 참고한다.

## 파일 구성
- `references/checklist.md` — 분야별 점검 항목과 흔한 실수
- `references/severity.md` — 심각도(높음·중간·낮음)와 머지 판단 기준
- `templates/report.md` — 결과 형식
- `examples/sql-injection.md` — 입력과 결과 예시

## 주의할 점
- 실제 위험이 있는 것만 짚고, 취향 차이(따옴표, 줄바꿈 등)는 요청이 없으면 다루지 않는다.
- 확신이 없으면 단정하지 말고 "확인 필요"로 표시하고 무엇을 확인해야 하는지 적는다.
- 결과는 사람이 검토할 의견이다. 실행해 보지 않았으므로 최종 판단은 담당자가 한다.
- 코드에 비밀번호·키·개인정보가 보이면 결과에 옮기지 말고 "민감 정보 포함, 제거 필요"로만 알린다.
- 참고: 공개 프로젝트 Alibaba Open Code Review(Apache-2.0)의 점검 분류를 참고해 사내용으로 새로 썼다.
