# 테스트 케이스 작성

## 언제 쓰나요
- 기능 개발이 끝나 QA 에 넘기기 전에 확인할 항목을 빠짐없이 뽑고 싶을 때
- 요구사항 문서를 받아 테스트 계획을 세울 때

## 입력
- 요구사항 목록, 기능 설명, 화면 설명 중 아무것이나(한 줄에 하나씩이면 더 좋다)
- 선택: 입력값의 범위·형식(예: 비밀번호 8~20자), 사용자 권한 종류, 우선 테스트할 부분

## 진행 방법
1. 요구사항마다 `references/techniques.md` 의 기법(동등 분할, 경계값, 상태 변화, 권한, 예외·오류, 보안 입력)을 적용해 케이스를 뽑는다.
2. 각 케이스의 우선순위는 `references/priority.md` 기준으로 매긴다.
3. 결과는 `templates/test-cases.md` 형식으로 쓴다. 예시는 `examples/` 폴더를 참고한다.
4. 요구사항에 범위·형식이 없어 경계값을 정할 수 없으면, 값을 지어내지 말고 "확인 필요"에 질문으로 남긴다.

## 파일 구성
- `references/techniques.md` — 테스트 설계 기법과 언제 쓰는지
- `references/priority.md` — 우선순위(상·중·하) 기준
- `templates/test-cases.md` — 결과 형식
- `examples/login.md` — 로그인 요구사항 → 테스트 케이스 예시

## 주의할 점
- 요구사항에 없는 기능을 만들어 테스트하지 않는다. 필요해 보이면 "확인 필요"로 묻는다.
- 실제 비밀번호·개인정보를 테스트 데이터로 쓰지 않고, 가짜 값(예: test01, P@ssw0rd!)을 쓴다.
- 결과는 검토용 초안이다. 실제 시스템 규칙과 맞는지 담당자가 확인한다.
